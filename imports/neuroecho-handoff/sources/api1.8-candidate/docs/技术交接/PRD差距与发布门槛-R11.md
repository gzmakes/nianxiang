# R11 发布与 PRD 差距复核（只读审查）

结论：R11 主要补齐了 R10 **心情写入在回执丢失后的可查询、同请求重试与停止**，对应 PRD F11/F12 的一个具体子集；它没有把原生源码变成已验收的手机 App，也没有完成云同步、硬件或商业验证。不宜据此宣称“各端完成”或“达到 90%”。

## 仍须保留的发布门槛

1. **安装包与设备运行。** iOS 需 SDK 构建、模拟器/真机、文件权限、键盘、VoiceOver 与前后台/进程恢复；Android 需 Compose/Gradle 编译、lint/assemble、真机/TalkBack/进程恢复。已有宿主 Foundation/Kotlin/HTTP 证据不替代这些；用户当前选择不安装 SDK，应按“可交开发的源码包”交付。Mac 最终 GUI、签名/公证与 Windows 实际 exe 启停仍须分别核验，离线组装不等于运行成功 [2:3,37,49–53]。
2. **安全手机接入和真正同步。** 当前是单用户本机 FastAPI/SQLite 的持续对话。手机的 127.0.0.1 不指向 Mac；需要另设计 HTTPS、身份/配对、设备隔离、撤回传播、版本/事件游标、离线冲突与去重，再考虑跨设备接入。不能直接把当前本机服务开放到公网 [1:16；3:7–9,70–79]。
3. **真实资料与陪伴闭环。** 连接状态、已有登录、实际读取、模型调用、被理解/纠正、重新打开后沿用修正是独立验收项。至少对选定的一份来源及“先听我说/再问是否要建议”的自然对话做当前版本人工走查；保留“暂不新增账号授权”，不得将 capability flag 或合成测试当成账号已通 [1:8,11；2:39,55；4 F01/F07/F09/F21–F23]。
4. **硬件只承诺可核验能力。** MindLink 的真实帧时间/序列/质量、断连退避、本地停止、实际输出 ACK 与重复命令去重仍需队友设备联调；专注度不能当情绪识别。Rokid 需确认具体型号/平台 SDK，再验输入/输出和权限。PRD 要求的记录/刺激隔离、实体停用、无 ACK 显示未知不能被 UI 占位替代 [4 F02–F06/F16/F20/F24；§11；2:45,55]。
5. **使用与商业证据。** PRD 提出的 6–10 名成人探索测试尚不是已有结果；应先选一个具体场景，记录任务完成、理解与纠正、打扰/退出、愿意再用的原因，再分开验证愿意佩戴与给定价格/替代方案下愿意支付。需计硬件、清洁/支持、云与模型/语音等完整成本。演示喜爱、候补名单、真实付款和留存不可混称；本轮不新增支付或外部邀约 [4 §11–12]。赛事资源/提交规则是本地 PRD 的历史记录，正式提交前另向主办方核对，不能当作本次已验证的现行规则 [4 §23]。

## 下一轮最小建议

先冻结同一版本的源码、契约、文案与各平台交接包，保留未完成门槛；再做一条“聊天 → 明确手记 → 断网未知 → 查询/停止 → 重开核对 → 删除不复活”的用户验收，随后进入手机 SDK/设备与硬件联调。继续共用契约/文案/设计 token，但布局和交互仍须平台验收 [3:24–33,48；4 §23]。

架构保留当前模块化单体，暂不引入微服务、GraphRAG 或跨端 UI 重写。新增账本的终态身份不应随意 TTL 清掉，否则旧请求可能重新执行；未来备份/保留策略要保持“删除后不复活”的不变量。这是后续产品化门槛，不是已确认的当前 bug [3:3,75–79；4 §10；5]。
