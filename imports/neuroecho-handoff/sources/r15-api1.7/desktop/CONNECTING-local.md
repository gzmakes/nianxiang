# 桌面连接到已经运行的本机服务 · R15

Web 和桌面要继续同一段对话，需要使用同一个服务。桌面不复制 Web 的模型密钥、数据库、浏览器草稿或待核对请求。

1. 先在 Web 地址栏确认当前的 `http://127.0.0.1:端口`。
2. 在桌面菜单／托盘选「连接与空间…」，或设置中的「连接与空间」。快捷键为 `⌘⇧L` / `Ctrl+Shift+L`。
3. 输入完整地址，点「核对地址」。只接受精确的 IPv4 回环地址和 1–65535 端口；不接受 localhost、别名、路径、查询、账户信息或网络地址。
4. 核对地址、同一持续对话和 API 兼容性，读完范围并勾选，再点「连接这段对话」。真正切换前会再次核对同一服务、同一对话。
5. 如需回去，在同一页点「返回桌面原来的本机空间」。切换不会合并或清除任何原空间资料。

不扫描端口，不新增账号，不修改网络监听、系统权限或模型设置。核对阶段只 GET `/api/capabilities` 和初始 `/api/conversation/changes`，有整体超时、16 KiB 上限且不跟随重定向。需要本机 `local_single_user` 服务，API 主版本 1、次版本至少 7，且支持 `conversation_change_cursor`。不会拿模型配置或对话正文作为连接探测。

## 数据、窗口和权限

- `userData/desktop-connection.json` 只保存地址、服务／持续对话身份和兼容版本；原子写入权限 0600，不存口令、token 或模型 key。身份编号仅内部校验，不展示给用户。
- 原空间保留原来的 Electron 存储分区。每个已选服务按地址＋服务身份＋持续对话身份的 SHA256 使用独立持久分区。草稿和 unknown 请求不搬移、不重新提交。切换时保留隐藏的原窗口，返回时继续原窗口中的草稿。
- 下次启动只尝试原来明确选择的服务。离线、身份变化、无效选择记录都会打开连接页，不自动进入另一个空空间。重新核对同一身份时继续其原分区；明确选择新身份会使用新分区。
- 共享服务页面使用受限 `shared-preload.js`：只有只读 `info()`、接收菜单命令的 `onCommand()` 和无参数 `openConnectionSettings()`。后者只打开可信 file 页，不接受地址、不连接、不写服务。
- 共享窗口不能调用 owner 文件桥、状态写入或原生通知 IPC。主进程始终核对当前实际窗口、顶层 frame、连接角色和 origin。共享分区拒绝权限、设备访问、下载及外部 origin 请求／重定向。
- 共享模式停用主进程通知器、托盘摘要读取与快捷输入面板；托盘／快捷键只唤起当前对话。网页内普通前台功能按所选服务自身规则运行。原服务由原启动方管理，退出桌面不会停止它。
- 桌面曾自己启动的原空间服务在切换后继续运行，以保留原空间；退出桌面只停止自己的 lifecycle。启动尚未完成时退出也取消 pending owned 启动；借用／外部服务不被结束。

## 身份检查边界

共享窗口每次新主文档、每次非 GET/HEAD/OPTIONS 请求转发前先核对身份，不会重放或自动重试原请求。后台每 20 秒只读核对已选地址；失败会隔离旧窗口并打开连接页，菜单／快捷键不能重展已隔离页面。旧核对回调受 generation 约束，不能覆盖新选择。

这些检查属于多个 HTTP 请求；本机 owner API 当前没有原子 service-instance 写前置条件。因此不能保证阻止本机服务在探测完成和真正请求之间瞬间被替换，也不能宣称抵抗本机同端口的恶意进程。此轮没有扩展服务鉴权或开放 LAN。手机设备配对依然走独立 HTTPS/Bearer 入口。

## 验收与打包

Mac 和 Windows 打包器都要求 7 个新连接资源存在且为普通文件，并沿现有白名单复制；不会携带连接偏好记录或通知偏好记录。原开发指针打包方式继续保留。本轮没有新增运行时依赖。

`node --test desktop/test/*.test.js` 包含真实 Node HTTP 探测、只读预览、nonce 确认、身份更换、存储分区、窗口／IPC／通知隔离、启动与退出竞态。`python3 -B -m unittest discover -s desktop/test -p 'test_package_*.py'` 检查打包资源、隐私与旧路径。

实际 Electron 开发运行使用全新合成 profile／空 DB 和现有已校验的只读嵌入运行时；不访问账号或模型。启动、回环 HTTP、退出归属与共享服务存活属于运行证据。当前 GUI 因 Mac 锁屏未验；这不等于真实界面连接点击成功，更不等于 Windows exe 验收。最终冻结源码包仍需独立组装与 UI 复核。
