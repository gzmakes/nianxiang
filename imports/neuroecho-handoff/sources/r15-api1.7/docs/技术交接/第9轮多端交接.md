# 第9轮多端交接

本轮是可继续开发的多端整合源码候选。Web / H5 / Electron 与两份原生工程已有共同的持续对话、资料确认、记忆版本与跟进合同；**不能称所有端已经完成、功能完全齐平或“全端90%”**。iOS / Android 可以交给对应开发同学接续，但没有 IPA / APK、手机 SDK 构建、模拟器或真机验收。原生当前不自动主动问、不发系统通知。

最终源码根目录为 `outputs/念响-第9轮交付/念响-多端集成候选-R9`。原始 `outputs/念响-本机原型` 与 R8 交付保留；不要把旧文件整目录覆盖到当前候选。

## R9 新增与共同合同

| 能力 | 本轮实现 | 必须保留的语义 |
|---|---|---|
| 单一持续对话 | 各端使用 `/api/conversation` 同一主对话，不提供会话切换 / 重新开始，不展示 session 编号 | 普通草稿与话题只是本设备视图，不创建新对话 |
| 发送恢复 | 稳定 request_id、原 payload / 服务 / 对话快照；旧 pending 不补 time_zone 或联系新字段 | 超时 / unknown / 重开先 GET；不自动重发，不因后来4xx换新ID；新聊天才冻结时区 |
| 飞书预览 | 两原生合入完整有界预览，展示实际保留原文、length / extracted_length / truncated | 最多12000 Unicode字符；仅标题或生成理解不能当完整预览。确认后才 attach |
| 记忆 | 手动候选、原话明确选存、编辑 / 确认 / 忘掉，expected_version CAS | 409保留编辑内容并读取最新，再由本人明确确认；未知状态 / 回执不报成功 |
| once / daily 跟进 | 两原生补创建、时区 / 安静范围、每日完成当前次、暂停 / 恢复 / 取消 | daily 完成发送精确 occurrence_at；推进后按 created_due_at 对账原创建请求；未知规则只读。修改已存正文 / 时间没有编辑合同，不伪造编辑成功 |
| F5 边界 | 今天安静 / 暂停 / 恢复，GET / PUT companion-boundary，confirmed:true + expected_revision CAS | 默认不主动联系；冲突 / 未知结果先只读核对，不自动覆盖。边界改变 / 拒绝 / 撤源使全部旧许可失效（包括未来项），待办保留，恢复不复活旧许可 |
| 每条联系范围 | allow_contact 默认false；明确选择话题与5–180分钟窗口，过期不补问 | due 表示任务到点；review_available用于被动查看，contact_eligible / available用于主动联系；不能混用 |
| Web / 桌面主动呈现 | 使用统一 claim → recheck → finish、跨渠道/同话题重叠窗口一次机会、epoch及有效期保护 | false / unknown不重领；submitted只表示调用呈现接口，不证明送达、已读或任务完成。实际OS通知仍独立验收 |
| 原生呈现边界 | 保存 / 展示约定和共用静默边界、被动任务查看 | **iOS / Android没有自动轻问、claim投递或系统通知**，不能把同意开关当原生已触达 |

服务契约为 `1.3.0`，OpenAPI声明82条路径 / 91个HTTP操作。最终能力键为 `in_app_recurring_followups`、`companion_boundaries`、`bounded_followup_contact`、`unified_contact_claim`；客户端按能力准入，不能仅凭版本号推定账号、CLI或硬件可用。

“今天先别问”等本人直接控制在用户消息入库同一事务生效，模型是否成功不改变拒绝。服务器只认首个明确命令分句，不把引文 / 转述当指令；未配置全局通知规则时统一quiet按该条明确时区计算。该规则已有后端定向检查，不代表真实用户体验闭环已经完成。

## 多端同步的协作方式

1. **先改共同语义。** 行为变化先更新API字段 / 能力、错误语义和版本；跨端确认旧pending如何兼容，再改各自界面。边界与许可的作用范围必须来自同一服务规则。
2. **共享资源不是整页自动同步。** 颜色、导航、默认偏好与F5核心文案由 `shared/` 生成；Web / H5 / 桌面共用页、Swift和Kotlin实际引用生成常量。新文案 / token还需迁入真实组件并验证；已保存偏好不能被新默认值覆盖。
3. **一项变更同列四端验收。** 变更单至少写Web/H5、Electron、iOS、Android的已改文件、已跑检查、未验路径；共享字段生成成功不代表原生编译或所有手写布局一致。
4. **冻结后打包。** 先完成shared/API同步、资产stamp与严格检查，再跑对应测试与实际GUI，冻结同一份源码，最后生成源码ZIP / 桌面包 / 逐文件hash。修改JS/CSS后必须重新stamp，不能沿用旧缓存URL。

普通草稿、话题、偏好与pending按服务地址保存在本机，不是云端多设备同步。对话 / 记忆 / 跟进共用同一服务数据，也不等于远程身份认证、实时推送或离线合并已实现。

## 接手与打包

- iOS：打开 `native/ios/Echo.xcodeproj` 的共享Echo scheme；接手人配置自己的Team。完整SDK构建、模拟器 / 真机、文件安全作用域、动态字体 / VoiceOver、键盘和后台恢复另验。
- Android：打开 `native/android`，使用JDK17 / SDK35；Compose类型编译、APK/AAB、TalkBack / 大字、设备生命周期和网络恢复另验。当前没有可交付APK。
- Windows：在Mac组装源码与官方运行时不等于Windows执行；最终便携包必须在Windows验证启动、中文路径、CLI、通知与退出归属。Windows时区依赖须带tzdata。
- 手机真机不能使用Mac的127.0.0.1；现服务为本机单用户、回环监听，没有远程认证 / 配对。先设计可达HTTPS与身份，不把个人服务直接开放公网来冒充打通。
- 来源仍取决于服务端既有CLI / 账号权限；本轮没有新增账号授权。EEG / Rokid仍待队友硬件联调，不把专注度当情绪、不伪造连接。支付未接入。
