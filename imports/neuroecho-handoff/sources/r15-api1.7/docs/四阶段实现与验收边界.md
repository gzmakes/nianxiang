# 四阶段实现与验收边界（2026-10-30）

## 1. 陪伴对话

- 使用单一持续对话。`SOUL.md` 在每次实际模型调用前读取；文件缺失、过大或无法读取时使用内置基础规则。
- 用户明确说“认真一点”或“活泼一点”时，语气会跨轮保留。用户可以继续改回自然语气。
- 模型用自然段回复时，服务端最多分四次按时间展示。刷新可恢复展示进度；用户发新消息或停止时，服务端截断尚未到时间的部分。时间推进不是逐段已读回执：离线时钟仍会走，网络延迟可能使服务端判断与屏幕最后一刻可见内容不同。
- Web/H5 支持文本和项目内原创表情同条展示，也可读取本机自行安装的 DSH 图库。图库不会随交接包分发。浏览器的“朗读”需要用户主动点击，现场调用系统语音合成，不生成或保存语音文件。效果受浏览器和系统语音支持影响。
- 本次工作环境未检测到可用模型配置，未完成 DeepSeek 真实网络调用。启动后在“更多 → 数据与模型设置”配置自己的服务地址、模型和密钥并测试，未配置或失败时不能把规则回复当成模型成功。已经运行的旧服务需要重启才能加载新代码。不要将本机模型配置或密钥提交、发给队友。

## 2. 记忆

确认、纠正、删除及来源撤回延续现有能力。普通话题按有限词语匹配选择相关记忆；对明确确认的回应偏好使用专门规则，并允许当前指令覆盖。匹配不是语义搜索，可能漏召回；候选和推测不应当作用户确认的事实。来源或记忆在生成期间变化时，旧回复和未展示的待确认草稿会被丢弃。

## 3. 一件真实任务的边界

模型有条件地使用只读工具检索用户已经接入的资料；明确要求提醒时可生成草稿。草稿本身不创建系统提醒，需要用户打开预览、核对并确认执行。成功、失败或仅保存在本机由执行回执区分；当前系统提醒接口只写标题，不设置到期时间。用户也可以在 Today 里自行创建本机跟进，其确认保存、完成、暂停等以服务端回执为准。模型工具调用目前通过模拟模型和进程内 HTTP 验证，真实模型及外部服务的完整闭环仍需现场验收。

## 4. 主动跟进、跨端与设备

- 本机跟进需用户主动创建，可选一次或每天及安静时段；页面在前台时最多每 30 秒检查。关闭页面或服务期间不会通知，也没有系统推送；重开后可见待处理事项。详见 `本机跟进与主动提醒.md`。
- iOS/Android 源码支持按服务端顺序恢复分段，Android 的草稿按服务地址隔离。后端仍仅监听本机，尚无安全的远程设备认证、真正的跨设备联网或同步。模拟代码检查不等于手机编译与真机验收；原生端表情图片及语音回复尚未接通。
- MindLink 只在用户同意后读取专注度，并检查来源、新鲜度、质量和断连；不据此推断情绪，也不自动发送给模型。已补个人模型来源适配，但未开放到页面；目前使用模拟 HTTP 响应，等待队友的设备现场联调。详见 `MindLink-v1联调说明.md`。
- Rokid 保留规划，需具体型号、SDK 和设备后再接入与验收。

## 本轮测试

排除真实数据库和本机模型配置的隔离源码副本中，Python 485 项、21 个子测试通过；一项需要 TCP 监听的测试未运行。Web/H5 和桌面 Node 测试 393 项通过。原生 iOS 宿主合成检查和 Android JVM 39 项通过，不代表手机真机通过。测试使用本机已有依赖，未证明新电脑可从零安装。

团队目录 `01_当前可运行原型` 是共享源码副本，运行时数据库、密钥、账号授权、依赖和缓存均不应打包。根目录 `05`、`06` 有历史素材与截图，可能包含个人信息，分享前逐项审阅。
