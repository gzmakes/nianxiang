# 开发与调整记录：陪伴主链

日期：2026-10-30  
依据：《念响-PRD逐项差距与决策清单》及用户“直接开始开发，保留开发记录和调整记录”。本轮优先做情感陪伴的一个可验收闭环，不把候选／占位写成已接通。

## 本轮目标

1. 用户可以表达“先听我说”或“一起梳理”，而不是先经历欢迎弹窗或选择新会话。
2. 回应偏好先由本人决定并确认；确认后在后续回复中可见地生效，纠正、删除和本次临时要求要正确处理。
3. 评估一次用户明确同意的跟进所需的调度、取消、回执和设备环境，不以保存记录冒充通知。
4. Web/H5 与现有 API 行为对齐，保留同一持续对话和现有来源撤回边界。

## 调整决定

- 选择私人陪伴 B 为主线；工作书签和交易者方向保留为候选，不以此替代体验目标。
- 以用户最后提供的 `design.md` 和单一对话、无欢迎弹窗为准。
- 只在用户确认之后保存跨次偏好；未确认推测不能进入确定事实。用户当前明确表达优先于旧偏好。
- 飞书等既有来源保留当前授权边界；GitHub/Notion 暂不新增账号授权。脑机与 Rokid 只做现有状态和接口准备，真机之后联调。
- 测试使用隔离数据及合成模型；不访问真实对话数据库或真实私人文档。源码备份位于工作区 `work/backup-before-companion-development-20261030`，未复制数据库或凭据。

### 决策 01：一次跟进先采用应用内呈现

现有本机“提醒”只是一条动作记录，Mac 提醒事项适配目前只写标题；系统通知也没有完整调度和交付验收。决定先新增独立的一次性跟进记录：用户明确填写内容和时间并确认；到期后在**打开的回响内**展示，关闭期间不声称发出系统通知，再次打开可看到已到期项。可以取消或标记完成；不自动发消息、不静默创建系统日历。

时间保存为带时区的绝对时刻；网络重试使用同一请求标识，重复请求不能创建两条。到期仅是“可在应用内展示”，不代表用户已看到；用户明确操作才变为完成或取消。需覆盖离线重开、并发、时区、导出与删除的验证。

### 决策 02：不确定的保存结果保留原请求

首次提交明确收到服务端 400／422 时，保留内容供用户修改。若请求曾超时、中断或收到无法确定结果的响应，即使后续收到 400／422，也不能排除旧请求迟到，继续保留原请求标识并提示核对；不会自动用新标识重复创建。iOS 和 Android 的持久化与真机网络中断恢复仍需设备实测。

本轮是 PRD 差距清单的第一批开发，不表示整份 PRD 完成。实际 DeepSeek 网络回复、真实浏览器点击链路、桌面应用启动、iOS／Android 构建安装和跨设备连接仍需在允许本机监听、具备对应 SDK 的环境验收。若已有旧服务在运行，应正常关闭后重新启动才能加载服务端变更；未对真实数据库执行迁移或更改。
