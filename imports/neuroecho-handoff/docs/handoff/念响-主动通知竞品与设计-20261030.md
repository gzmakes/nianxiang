# 主动通知：竞品观察与回响的边界

更新：2026-10-30。本记录优先使用产品或平台官方资料。官方介绍代表产品方的功能描述，不等于本次对其账号、算法或所有设备的实测。

## 竞品与平台做法

| 产品或平台 | 可核对的做法 | 对回响的启发 |
|---|---|---|
| Today | 官方将主动发现、产生建议和通知视为不同环节；产品介绍强调每日简报、对变化的跟进和用户可行动的信息。[能力介绍](https://today.ai/articles/capabilities)、[产品介绍](https://today.ai/articles/blog/what-is-today) | 通知应有明确原因和可执行去处；“生成了一条建议”不等于“已经送达”。不能据此推断 Today 内部的具体频率阈值。 |
| Replika | 官方说明用户可以开启通知，收到基于过往对话的跟进或问候；公开帮助没有给出可核验的统一频率和静默策略。[通知帮助](https://help.replika.com/hc/en-us/articles/360027515872-How-do-I-set-up-my-app-s-notifications) | 陪伴式关怀需要单独的用户选择和自然语气；不根据一次未回复反复追问。 |
| Apple | 通知指南建议避免对同一事项连续重复提醒，注意隐私信息；系统设置提供锁屏预览及专注模式控制。[通知指南](https://developer.apple.com/design/human-interface-guidelines/notifications/)、[Mac 通知设置](https://support.apple.com/en-ie/guide/mac-help/mh40583/mac) | 锁屏默认使用泛化文案；尊重系统勿扰，前台已有应用内提示时避免重复弹系统通知。 |
| Android | 官方提供用户可单独管理的通知渠道，并区分普通与高干扰通知。[Android 通知设计](https://developer.android.com/design/ui/mobile/guides/home-screen/notifications) | 未来可将约定提醒与主动关怀分渠道，不能把普通陪伴消息伪装成紧急通知。 |

## 建议的产品分层

1. **用户约定的跟进**：用户明确选择内容、时间和是否重复。允许暂停、取消、设置安静时段；到期未处理仍能在应用内查看。用户可以关闭系统通知而保留事项。
2. **助手主动关怀**：依据用户明确允许的范围提出问候或跟进，独立开关、可限制时段和频率。默认不因为用户不回复而重复追问；超过合适时间的关怀失效，不攒成一堆补发。真实对话中可说明为什么想起这件事，允许用户说“不想聊这个”或“今天别提醒”。
3. **安全和隐私**：锁屏不展示对话、脑电或私事；不将专注度解释成情绪，不使用制造内疚或依赖的措辞。不得把系统调用成功写成“用户已看到”。

以上静默时间、间隔和条数是回响的产品配置，不是对竞品内部规则的断言。首轮采用的默认值是 22:00–08:00 安静、最短间隔 60 分钟、每天最多 3 次；这些都需要通过真实用户体验持续调整。考虑到限频可能延后某个用户约定的事项，设置页面应明示规则，并保留应用内事项。

## 运行边界

当前本机实现先支持**用户已确认的跟进事项**；模型自动识别生活变化并主动问候尚不是已交付能力。浏览器／桌面进程须运行，系统通知权限、系统勿扰和系统调度都可能阻止或延迟提示。进程关闭期间的后台能力、通知送达率与用户点击需独立实现与真机验收。

iOS 有由系统调度的本地通知机制，但需完成注册、取消、权限和真机验证；Android 的精确时间与后台调度受系统权限和省电策略限制。[Apple 本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)、[Android 精确闹钟](https://developer.android.com/about/versions/14/changes/schedule-exact-alarms)。
