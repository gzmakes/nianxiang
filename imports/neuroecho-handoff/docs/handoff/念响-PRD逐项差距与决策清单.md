# 念响：PRD 与当前项目逐项差距

核对时间：2026-10-30。依据是你提供的《念响·具身个人伙伴 PRD 0.4》本地 HTML、同目录的 `requirements.json`、`coverage-matrix.json`、`acceptance-cases.json`，以及当前 `outputs/念响-本机原型` 的源码、技术交接和现有验证记录。本次为只读对照，没有重新授权账号、连接真实硬件或新增功能。

## 一句话判断

现在已有的是一个**以对话、来源、记忆和本机动作记录为核心的个人伙伴原型**，有部分真实模型与来源闭环；还没有成为 PRD 描绘的、能稳定长期理解和主动帮助用户的完整多端实体伙伴。最大的落差不是界面数量，而是**长期记忆与分寸、可用的主动跟进、真实硬件反馈、移动端实际交付，以及隐私与真实验证**。

**不建议给出一个总体完成百分比。** 24 条正式需求的颗粒度、适用条件和验证门槛不同；功能片段可运行、整条需求完成、真机验收和产品价值成立是不同层次。PRD 的 96 条是想法／资料在文档中如何处理的覆盖记录，不是 96 个已经开发的功能；60 条是拟议验收案例，PRD 文件中结果尚未填写，不能用项目自动化测试数直接抵充。

## 先把后续决定放回原 PRD

1. PRD 0.4 中私人陪伴 B 还作为候选；你后来明确选择**情感陪伴 personal agent**，因此这份核对以 B 为主要方向。工作书签 A、交易者 C 保留为候选，不把它们没做完算作 B 的必需缺陷。
2. PRD 首期曾不要求四端同时开发；你后来要求 Web、macOS、iOS、Android 同步并新增原生客户端，因此四端落地与一致性是**后来扩大范围后仍未完成的工作**。
3. 你后来要求**只有一条持续对话、不用欢迎弹窗、直接聊天，输入附近展示连接入口**。原 PRD 的强引导连接流程不是应机械恢复的缺陷。保留首屏可发现连接、授权后真实读取并提供有依据的理解这部分价值即可。
4. Rokid 按你的新决定先做框架和占位；脑机设备在队友处，之后联调。两者未接通是明确可见的未完成项，不应说成赛前已打通。
5. 你选择暂不新增账号授权；GitHub、Notion 等未完成账号验收是待办门槛，不代表你已经同意新增授权。视觉以你后提供的 `design.md` 为准。

## 比“有没有页面”更重要的 9 个差距

### 1. 陪伴的长期体验：有基础，但还没有证明“越用越懂你”

目前可结合有限近期对话和确认记忆生成回复，也有可修改的人格文件和显式倾听模式。还缺事件时间线／日记／About Me、关系和偏好的随时间变化、跨话题上下文策略、旧信息过期与冲突解决，以及“纠正一次后下次真实改变”的长期体验验收。PRD 把部分时间线和创作回顾放在产品化路线，不全部属于当下 P0；但“确认的经历和回应偏好能被下一次正确使用”是私人陪伴主链的核心。

### 2. 主动性：能保存事情，不等于会在恰当时间跟进

Today 和任务页可以展示已有本机记录；目前没有完整的后台定时、事件触发、主动判断、静默时间、拒绝范围／到期、提醒预算和可靠通知交付闭环。消息没有自动发送，系统提醒目前也不带到期时间。要做“明天再问我”，必须先有明确同意、时间、状态持久化、实际触达、关闭与失败回执。

### 3. 来源接入：目录比真实接通范围广

- 本机文本、Git：历史记录有使用合成材料的真实读取、预览、接入、模型问答验证；它们是用户选定快照，不是全天扫描／持续同步。
- 飞书：有 CLI、单篇读取、预览、接入及先前真实账号读取记录；本轮没有重新验证当前账号授权与数据可读性。
- Apple 日历／提醒：有 Mac 系统适配；权限和真实系统对象写入／回查未完整验收，手机端不是读取手机自己的日历。
- GitHub／Notion／Gmail：有不同程度适配代码，当前没有完成你允许范围内的新账号授权和真实读取验收。Gmail 当前是应用专用密码／IMAP 路径，不应说成 Google OAuth 已做好。
- HealthKit／手表、Rokid、米家：不应因有目录、研究或占位而写成已联调。Rokid 具体型号、系统与 SDK 路线需后续确定。

### 4. 执行能力：是受控的有限动作，不是通用后台 Agent

当前主要是消息草稿、提醒／日历的预览与本机保存，Mac 系统写入仅为需权限和验收的可选路径。没有通用浏览器／CLI 自主执行框架、跨应用任务编排、持续后台工作、真实消息自动发送或任务完成后通用撤回。PRD 本来也不要求首版做“通用 OS／万能代理”；优先把你选定的单个 B 场景闭环做真，而不是用不真实的连接图标凑数量。

### 5. 硬件与 BCI：代码桥只是第一步

队友已有实时专注度计算和小球 Demo 是队友的反馈；当前项目有读取 MindLink 的代码和质量／时效门，但没有在这台产品上接到他的真实设备。还缺真实流、噪声／人脸动作污染、断流和停止、设备可控输出、ACK、基线及固定反馈对照。头环提供的**专注度不能解释为焦虑、难过或其他具体情绪**。RSC 的历史设想与队友现有设备／接口，须先按实物核对，不要硬把一种说成另一种。

### 6. 手机与跨端：有原生工程，还不能交付安装使用

| 端 | 目前能确认 | 主要差距 |
|---|---|---|
| Web | 本机浏览器原型与相关历史 UI 验收 | 真正长期使用、不同浏览器／设备与全链权限未全部验收 |
| H5 | 与本机服务共用一条对话的手机网页代码 | 桌面浏览器截图不是手机真机；当前本机回环不让其他手机直接访问 |
| macOS | Electron 开发版，窗口与部分记忆操作曾实测；窗口重开／最小化恢复已修 | 未公证签名安装包、自动更新；快捷条、系统文件选择／通知完整系统体验未全面验收 |
| iOS | SwiftUI 源码，Foundation 25 项合成契约与宿主生命周期 4 项等记录 | 无 iOS SDK 构建、IPA、模拟器或真机。搜索只覆盖消息，缺手动新增记忆入口；连接导航有源码层风险待运行确认，系统动作只存本机 |
| Android | Kotlin／Compose 源码，14 项 JVM 测试及 API 元数据检查等记录 | 无 Android SDK 构建、APK、设备 HTTP／真机。搜索只覆盖消息，连接范围较 Web 窄；系统动作只存本机 |

同一台 Mac 服务上的单条对话 ≠ 两台设备安全同步。账号、设备配对、HTTPS 可达性、身份与资源隔离、跨端变化通知、离线恢复及并发编辑冲突均需建设。已有共享 token／文案／API 快照与生成器，但各端尚未全部引用，成功响应 schema 也未补齐，不能说改一处就会自动同步所有端。

### 7. 隐私、授权与可追溯：需要产品化

当前有按来源范围告知、确认、来源撤回、基本审计与导出；但模型收到的**实际完整内容**未做到发送前逐项可查，导出范围不等于数据库完整备份，删除无法追溯至外部服务或全部备份。模型服务的真实处理方、保留／训练政策、用途授权和比赛赞助路由数据限制需按实际选择核实；代码能够发送，不等于真实私人资料已经适合发到任何路由。脑电默认留本地只是目标，真实原始数据缓冲／清理须以实际设备方案验收。

### 8. 安全与可信反馈：已有规则，仍需覆盖真实边界

已有停止、过期信号不使用、来源撤回期间避免旧结果落库、动作未知不假报成功等保护，也有针对明确危险语句的有限兜底。仍缺完整的长期拒绝范围、真实硬件紧急停止与重连、隐私数据生命周期、手机授权与远程用户鉴权，以及足够的异常与人工体验测评。规则兜底不能当作医疗或危机干预能力。

### 9. 商业与用户验证：是未验证，不是缺一张支付页

PRD 希望验证：用户愿意回来、愿意承担硬件佩戴成本、理解价格后愿意为具体收益付费，并做软件／实体／实体＋EEG 的对照。目前没有足够的真实用户访谈、留存、付费或 BCI 增益数据。账户、支付、价格、订阅、机构购买、向外售数都不能因 PRD 有设想就说已经确定；竞赛规则与赛中资产复用需以实际主办方要求为准。

## 建议你做的产品判断

下面是我的建议，**不是 PRD 已经批准的排期，也不是对你此前决定的重新提问**：

1. **先冻结一个陪伴时刻。** 例如：用户受挫后说“先听我说”→ 回响基于本人确认的经历回应 → 用户纠正“下次先听”→ 下次真的先听。只选一个能当场检查的结果；工作书签保留为次路径。
2. **选择主动跟进的第一种动作。** 推荐先做由用户明确提出并可取消的“一次定时跟进”，连同实际触达、关闭、未知和失败回执，而不是先宣称全能自主 Agent。
3. **决定第一条真实资料主链。** 推荐先保证已有本机文件／一篇已授权飞书文档 → 有来源的理解 → 用户纠正 → 下一次回应真正使用；其余连接只在授权与可用条件满足时扩展。
4. **明确硬件在主故事中的作用。** 队友接入后，先展示专注度实时可见、质量不足即停止、用户可随时退出；再讨论是否驱动一个可关的反馈。它能否改善陪伴体验需要与无 EEG 版本对比，不能由“数值变化”直接证明。
5. **确定移动交付门槛。** 如果比赛展示需要手机实机，先选一台目标设备完成安装、可达的安全后端与五条主流程；若当前以 Mac 展示为主，诚实标明原生工程与安装包未完成，同时让技术团队继续编译联调。两个平台最终都要补，先后顺序是资源决策。

推荐验收顺序：① 对话与可纠正记忆的同一条主链；② 一份真实来源；③ 一次用户明确授权的动作／跟进；④ 一个有质量与停止的真实脑机／硬件演示；⑤ 目标手机安装和跨端验收。并行推进可以，但不要把测试按钮、账面记录或画面状态当作外部执行／真机成功。
