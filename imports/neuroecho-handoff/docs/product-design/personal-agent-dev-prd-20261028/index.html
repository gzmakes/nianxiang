01

先读这一页

为谁、何时： 首批验证对象是有具体经历想讲、愿意对私人AI表达的成年人。首个验证情境：一次受挫交流后，想把话讲完，不想再解释背景或立刻被说教。不是按职业泛称“所有白领”。

解决什么： 旧聊天要重讲背景；AI常直接给建议；本人纠正后下次仍照旧；主动提醒可能越界。这些是待真实用户验证的痛点。

交付什么： 一段可选择倾听/梳理的交流，以及本人确认的经历与回应偏好；下次能接着聊，只有获准才轻问。用户已明确选这个主场景，工作书签与交易者移出首期。

已确定： 软硬件＋BCI方向、RSC系列租赁、Today式连接冷启动；Rokid为眼镜主候选。型号/SDK/实体输出待验，眼镜不进入首期必做。

本期只验证： 一份资料能否让人更容易开口；一次纠正能否使下一次先听再建议；硬件/EEG有无增益且佩戴成本是否值得。

02

用户只走一条路

  1. 带入背景： 选择一份自我说明/近期记录，或手动讲一件事。
  2. 得到回应： 一句有依据的开场；选择“先听我说 / 一起梳理”。
  3. 纠正理解： 讲完后纠正理解，选择是否记住；不把推测当经历。
  4. 自主体验： 自愿开启硬件反馈，随时暂停/停止。
  5. 再次回来： 采用新回应偏好续聊；若本人允许，在约定窗口轻问一次。

不会要求先连接两个来源、先填人格问卷或一直戴着脑电帽。

体验例： 用户说“刚才那次交流有点难受，先别帮我想办法”；伙伴回应“好，我先听”。结束时本人确认“下次先问我要倾听还是建议”；再次进入采用这个偏好，未经同意不追问旧事。

F1

连接后马上有内容

从自我说明或近期记录开始，先问一个与本人有关的问题。

做到什么算完成
授权后首卡能定位真实原文；缺资料不编造；用户只连一个也能推进。

工程细节 · 应用＋产品

输入 本人选定的一份非敏感自我说明/近期记录；从飞书读取，也可手动输入。

行为 首屏保留手表/日历/飞书入口。飞书授权后只读选定记录，展示事实、待确认理解和一个问题，例如“你想先讲完，再一起想办法吗？”

边界 首期只实现飞书真实连接；手表/日历标“稍后支持”。不扫全库，不把登录成功说成读懂了。

失败 取消、过期、无权限、空内容分别提示；可换资料/手动输入，连接验收仍记未通过。

追溯到长版需求：F01, F21, F22

F2

先弄清要倾听还是梳理

用户不用面对空白框，也不被迫接受建议。

做到什么算完成
用户说“先听”后不再给方案；用户主动改意图才转梳理；旧回复不会抢答。

工程细节 · 产品/设计＋应用

输入 首张卡与用户当前发言。

行为 提供“先听我说 / 一起梳理”；合并连发回合，新输入取消未展示的旧回复。每轮只推进一个问题。

边界 不机械拆成很多气泡；倾听时不排任务。“今天先别问”覆盖后续主动提议。

失败 模型超时保留用户输入，允许重试；不伪装已得到结论。

追溯到长版需求：F07, F08

F3

记错可以改，下次真的变

事实、推测分开；本人确认后才成为长期记忆。

做到什么算完成
纠正后重开仍采用新版本；删除后不再检索；未确认推测不进入确认记忆。

工程细节 · 应用

输入 带来源的理解卡，以及用户确认/纠正。

行为 保存本人确认的一条经历或偏好、来源、有效期与版本；再次进入用最新版。提供编辑、删除、导出。

边界 临时状态不写成人格；角色虚构状态不作用户事实。换模型不清空用户记忆。

失败 保存失败显示未保存；断开来源后停读，并清理对应缓存及派生记忆，迟到结果作废。

追溯到长版需求：F09, F14, F23

F4

真实硬件在场，随时能停

实体键一按进入陪伴；自愿开启RSC相对反馈，不佩戴也能聊天。

做到什么算完成
日志能追到真实帧与实物变化；停止在拟议2秒内生效。回放不能算实时验收通过。

工程细节 · 脑机＋硬件；应用协作

输入 实际RSC帧、时间、质量和本次采集授权。

行为 实体键启动/暂停/结束，圆形终端提供低干扰在场反馈；用户自选固定灯效或有效EEG的有限相对映射。坏质量回中性，命令需有回执。

边界 只记录，不刺激。EEG不决定聊什么、是否存记忆或主动追问；不推断情绪原因。原始EEG不送模型，历史/合成/实时明确标记。

失败 断流、坏质量、撤销立即停映射；云端不可用仍能本地停止。SDK未知时只能验接口模拟。

追溯到长版需求：F02, F03, F04, F05, F06, F16, F20

F5

下次记得，也知道什么时候不问

留下一张本人确认的陪伴记录；主动跟进默认关闭。

做到什么算完成
重开记得本人确认的内容且回应方式已变；未同意不主动问，约定范围最多一次，拒绝后保持安静。

工程细节 · 产品＋应用

输入 确认的经历摘要、回应偏好，以及是否/何时允许再问。

行为 保存一个陪伴记录对象。用户再进入同一话题时采用新偏好；仅在本人约定的时间窗、话题和App在线条件内轻问一次。

边界 “先听、不建议”继续生效；拒绝或静默优先。不在线则不补发过期提醒；首期不做后台跨端通知。

失败 未确认不保存；保存失败不报完成。拒绝/断开使排队和迟到提议失效，重复事件不重复追问。

追溯到长版需求：F07, F09, F10, F11, F12

04

技术与建设顺序

建议基线： H5界面＋本地采集/CLI桥＋FastAPI服务＋SQLite＋一个模型接口。确定状态机起步；不要先叠多个Agent框架。

顺序 产物 复用 / AI可辅助 必须人工验
① 接口与状态 事件、来源、记忆、结果四类契约 AI写schema/页面/模拟适配器 字段语义、权限和失败状态
② 两条输入 一份文档＋一段真信号 官方飞书CLI；厂商SDK/RSCAdapter 真实授权、资源范围、质量/时序
③ 一个交互闭环 来源卡→纠正→确认记忆 AI写受控状态机/存储/回归用例 自然交流、重开、删除传播
④ 一个实际结果 一张陪伴记录＋实体反馈 AI写结果卡与显示协议 真实记忆、回应变化、反馈/停止
⑤ 比较和展示 对照记录与单Case演示 AI辅助日志整理、图表 用户收益、佩戴成本、来源真实性

客户端/应用负责F1—F3；脑机/硬件负责F4；产品与应用共同负责F5，产品负责验收。正式排期按可用人时填写，设备等待不算代码工时。

四类最小数据： Source保留对象/位置/版本/模式；Memory保留原话/确认状态/有效期/修订；Sensor保留设备/时间/质量；Result保留批准版本/幂等键/对象ID/状态，以及允许再问的话题、时间窗、次数与拒绝失效标记。既有详细契约放附件，凭据留服务端。

数据边界： 仅记录，原始EEG留本地；非敏感测试文档先验链。模型处理范围与保留政策先核定；无合适条件不发送私人/公司/生理数据。网页不得提交任意shell命令。
